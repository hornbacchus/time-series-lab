# PELT Change Point Detection

## What It Does

PELT (Pruned Exact Linear Time) detects **multiple change points** in a time series -- moments where the statistical properties (mean, variance, or both) shift abruptly. It finds the optimal segmentation of the series by minimizing a penalized cost function, identifying the number and locations of change points simultaneously. PELT achieves this with linear computational cost in the series length, making it practical for large datasets.

## When to Use It

- You suspect your series has undergone one or more abrupt shifts in mean or variance
- You need to segment a time series into homogeneous intervals
- You want an automatic, statistically principled method to find the number and location of change points
- Quality control applications require detecting process shifts
- You are preprocessing data and need to identify structural breaks before modeling

## Key Assumptions

- Change points are abrupt (instantaneous shifts, not gradual transitions)
- The number of change points is unknown and must be inferred
- Within each segment, the data is generated by a fixed statistical model
- The cost function correctly captures the type of change you are looking for
- The penalty parameter is chosen to balance detection sensitivity and false positive rate

## Outputs

- **Change point locations**: the estimated times where shifts occur
- **Number of change points**: determined automatically by the penalty
- **Segment statistics**: mean, variance, or other parameters for each segment
- **Cost function values**: showing the quality of the segmentation
- **Segmented series visualization**: the original series with detected change points marked

## Technical Details

**Optimal partitioning framework**: Given a series `y_1, ..., y_n`, find the partition into segments that minimizes:

`sum_{i=0}^{m} C(y_{tau_i+1:tau_{i+1}}) + beta * m`

where `tau_0 = 0 < tau_1 < ... < tau_m < tau_{m+1} = n` are the m change points, `C(.)` is the cost of a segment, and `beta` is the penalty for each additional change point.

**Cost functions**:
- **Change in mean (Gaussian)**: `C(y_{s:t}) = sum_{j=s}^{t} (y_j - y_bar_{s:t})^2`
- **Change in variance**: `C(y_{s:t}) = (t-s+1) * log(sigma_hat^2_{s:t})`
- **Change in mean and variance**: `C(y_{s:t}) = (t-s+1) * log(sigma_hat^2_{s:t}) + constant`
- **MBIC (Modified BIC) cost**: incorporates a segment-length-dependent penalty for more accurate detection.

**Optimal Partitioning (OP)** algorithm: Define `F(t)` as the minimum cost of segmenting `y_1, ..., y_t`:

`F(t) = min_{0 <= s < t} [F(s) + C(y_{s+1:t}) + beta]`

with `F(0) = -beta`. This dynamic programming recursion has O(n^2) cost.

**PELT pruning**: PELT accelerates OP by pruning candidate change point locations. If at time t, a candidate s satisfies `F(s) + C(y_{s+1:t}) > F(t)`, then s can never be optimal for any future time t' > t (under the condition that the cost function satisfies a specific inequality). These pruned candidates are removed from future consideration.

Under the condition that `C(y_{s+1:t}) + C(y_{t+1:T}) <= C(y_{s+1:T}) + K` for some constant K, PELT achieves O(n) expected cost when the number of change points grows linearly with n.

**Penalty selection**:
- **BIC penalty**: `beta = log(n) * p`, where p is the number of parameters that change at each break. Tends to underestimate the number of change points.
- **Modified BIC (MBIC)**: `beta = 3 * log(n)`. Better empirical performance.
- **AIC penalty**: `beta = 2 * p`. Tends to overestimate change points.
- **CROPS (Changepoints for a Range of Penalties)**: Run PELT over a range of penalties and plot the number of change points vs. penalty. Identify the "elbow" where adding more change points provides diminishing improvement.

**Minimum segment length**: A constraint `tau_{i+1} - tau_i >= l_min` prevents spuriously short segments. Typical choice: `l_min = 2 * p` (at least twice the number of parameters to estimate).

**Extensions**: PELT can be applied to multivariate series (joint change point detection across multiple channels) by using multivariate cost functions. Non-parametric cost functions based on ranks or kernel-based two-sample tests allow detection of general distributional changes.

## Interpretation

**Plain-Language Finding (Tier 1)** - count of change points as offline penalized optimum, cost model, penalty, most-recent CP with pre/post mean shift.

**Technical Interpretation (Tier 2)** - pruned exact linear-time segmentation under the chosen cost and penalty; contrast with BOCPD's streaming framework.

**Caveats (Tier 3, conditional)**:
- Low detection count on long series (n > 500, n_cp < 2) - penalty may be too high.
- Dominant segment (> 50% of obs) - verify within-segment fit.
